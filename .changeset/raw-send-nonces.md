A `connection.kms.getAccount` account now has a viem `nonceManager`, so its sends and the plugin's own sends from the same account get distinct nonces. For each send without a nonce, viem reads the node's pending count through the connection and skips the nonces the plugin used or reserved. With a client whose transport is `custom(connection.provider)`, the send holds the account's send lock until its raw transaction goes out or viem resets it after a failure, as a send through the plugin does. A client with its own transport, such as `http(url)`, releases the lock at once and reserves its nonce. Sends through the plugin skip that nonce until viem resets it or 60 seconds pass, and a warning says the broadcast is not ordered. No RPC answer is rewritten. Raw transactions from other senders, or that the plugin cannot decode, pass on untouched. A library send started from inside a send from the same account fails at once with `core.account.nonce-reentrant`. A send that waits 5 seconds behind a library send prints a warning, and another prints when the 60-second limit ends a hold. On an automining node, a plugin send can be refused with "Nonce too high" while a client with its own transport signs or broadcasts the reserved nonce. Send through `custom(connection.provider)` or wait for that send's receipt. The viem peer range is now `^2.55.13`, the first release that resets the nonce manager after any failed send. `getAccount` refuses an older viem with `core.account.viem-too-old` before any KMS call. `core.account.viem-missing` no longer names a package manager. The warning printed on the first transaction a library account signs is gone.

What should I do? If your project pins viem to an exact version below 2.55.13, such as `"viem": "2.47.6"`, bump it to 2.55.13 or later. Otherwise npm stops the install with a peer dependency conflict, `ERESOLVE`, and pnpm and Yarn install it with only a peer warning.
