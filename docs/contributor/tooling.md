## Where the CI jobs run

Linux jobs name the image, `ubuntu-26.04`, rather than `ubuntu-latest`, so an image change is a visible
edit in a pull request. Job names give the OS family (`Test (Linux, Node 22.13.0)`), not the image, so
that edit does not rename a required check.

| Event                               | Jobs                                                                                                                                                                       |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pull request                        | Every job in `ci.yml`: lint, docs, the Linux test matrix, coverage, package, LocalStack, examples, consumer typecheck, zizmor; and `Links an issue` from `pr-hygiene.yml`. |
| Pull request with label `ci:all-os` | The above, plus `Test (macOS, Node 22.13.0)` and `Test (Windows, Node 22.13.0)` from `ci-all-os.yml`.                                                                      |
| Push to `main`, merge queue         | Both workflows: the full matrix.                                                                                                                                           |
| Manual dispatch of `ci-all-os.yml`  | macOS and Windows.                                                                                                                                                         |
| Nightly and monthly schedule        | `mutation.yml` on Linux. The nightly run stops before installing when the core's code, tests, Stryker config and lockfile are unchanged.                                   |
| Manual dispatch of `mutation.yml`   | `mutation.yml`; with `force`, a full run.                                                                                                                                  |

A macOS runner minute costs about ten Linux minutes, so pull requests skip macOS and Windows by default.
To run them on a pull request, add the label `ci:all-os`: adding it starts both jobs, and they then run
on every push while the label stays. Add it when a change touches paths, line endings, shell commands,
file permissions or anything else that differs by OS. Adding any other label starts no test job.

Every merge to `main` runs the full matrix. The release workflow (#47) is to publish only commits on
`main`, so a release has run on Linux, macOS and Windows.

The required checks in `.github/ruleset-protect-main.json` are the jobs that run on every pull request.
The macOS and Windows checks are not required: a required check that never reports stays pending and
blocks the merge.
